# 乙六 試験対策アプリ（危険物取扱者 乙種第6類）

学び方の違う2つのPWA。依存ライブラリなし（HTML/CSS/ES Modules）、ビルド不要、GitHub Pages のサブパスで動作。

| URL（公開時） | 内容 |
|---|---|
| `/otsu6/` | 入口（どちらかを選ぶ） |
| `/otsu6/speed/` | 合格特化型（10段階：診断→重要事項→アニメ→一問一答→類題→間違い復習→苦手補強→科目別模試→総合模試→終了判定） |
| `/otsu6/full/` | 完全学習型（13段階：診断→基礎講義→図解アニメ→重要事項→基礎→標準→過去問(類題)→応用→原因分析→再学習→科目別模試→総合模試→終了判定） |

## 構成
```
shared/core/   学習エンジン（DOM非依存・テストあり）
  content.js     データ読み込み・索引
  store.js       端末内保存（localStorage）・バックアップ検証
  engine.js      採点・回答記録・習得度・復習優先度・再テスト
  exam.js        模擬試験（本番構成で出題・採点）
  completion.js  学習終了判定（7条件）と次の一手
  curriculum.js  2パターンの学習順序・今日の目標
  analysis.js    間違いの原因分類
shared/ui/     共通画面（演習・模試・教材・アニメ・進捗・記録・設定）
shared/anim/   アニメ教材21本（SVG、段階操作・静止画モード）
shared/data/   config.json（試験の公式値・確認日）／content/*.json（単元と問題）／substances.json（物質比較）
speed/ full/   各アプリの入口・カリキュラム・manifest・sw.js（自動生成）
tools/         validate.mjs（データ検証）／build-sw.mjs（SW生成）／make-icons.mjs／serve.mjs
docs/          RESEARCH.md（公式情報の調査記録）／CONTENT_SPEC.md（問題データ仕様）
```

## 学習終了判定（両アプリ共通）
目標＝公式の合格基準（各科目60%）＋20ポイント＝**各科目80%**。次の7条件すべてで「設定した学習目標を達成しました」。合格保証ではないことを画面に明記。
1〜3. 本番形式模試の直近の科目別正答率が80%以上（法令・物化・性消）
4. 問題の重なり20%以下の模試2回で、各科目80%以上
5. 重要度2以上の全単元の習得度80%以上（習得度＝異なる問題での正解。同じ問題の繰り返しでは上がらない。30日経過で割引）
6. 間違えた重要度3の問題が、すべて最新回答で正解
7. 直近の再テスト（10問以上・未回答問題優先）で80%以上

科目免除（乙種免状あり）を設定すると、性消10問・35分の形式で判定。

## 公式の過去問（各自が取り込む）
アプリにも公開リポジトリにも過去問は入っていない。利用者が消防試験研究センターの「過去に出題された問題」から「乙種第１，２，３，５，６類試験」のPDFを自分でダウンロードし、`#/past`（模試タブ下の「公式の過去問」）で取り込む。
- 処理はすべて端末内：pdf.js（`shared/vendor/pdfjs/`、Apache-2.0）でページを描き、`shared/core/pastimport.js` が画素から問題の範囲（「［問」の左端位置）と解答表の赤い数字（形の見本 `past-templates.js`）を読む。文字は読まない（PDFに文字情報がほぼ無いため）。
- 共通25問（法令15・物化10）＋第6類10問の35問を画像（JPEG）にして IndexedDB `otsu6-past` に保存（両アプリ共用・約2.8MB）。送信しない。バックアップには回答記録（state.past）だけが入り、問題の画像は入らない。
- 構成が想定（共通25＋10問×5類、解答表25・10×5）と違うPDFは取り込まずにエラー。読み取った正答は公式の解答表の画像と並べて利用者が確認・修正できる。
- 令和8年6月更新版（PDF作成日 2026-06-16）で、35問の切り出しと正答35個すべての読み取りを確認（2026-11-06）。PDFの形式が変わったら `tests/past.test.mjs` と実物で確かめ直す（実物PDFは `.local/` に置く。git管理外）。
- 根拠：公式の利用条件の「ご自身の学習のため」の例外と著作権法第30条（私的使用のための複製）。法律家の確認はしていない。解説は公式に無いので付けない。

## 使い方
```bash
node tools/serve.mjs 8811 /otsu6/   # Pages と同じサブパスで確認 → http://127.0.0.1:8811/otsu6/
node tools/validate.mjs             # 問題データの検証（エラー0が公開条件）
node --test tests/*.test.mjs        # エンジン・過去問読み取りのテスト（32件）
node tools/build-sw.mjs             # ファイルを変えたら公開前に必ず実行（SWの版を更新）
```
更新時はアプリに「新しい版があります → 更新する」が出て、版ごとに丸ごと入れ替わる（古いファイルが混ざらない）。学習記録は localStorage（キー `otsu6:speed:state` / `otsu6:full:state`）でキャッシュとは別。
